# From local workflows to a personal agent platform

This roadmap includes the changes from the independent review. The first release should let someone start a run in one project, open the dashboard in another, and recover the same run after a crash. The four shared workflows come next. Chat, desktop, the hosted service and mobile all build on the same local engine.

## Build and review order

Each numbered item below can be reviewed as one pull request (PR). Keep each phase on its own branch. Land its slices in order and review the phase before starting the next one. For a behavior change, run the existing suite, add a failing test first, then run the changed tests and the suite again. Use fake agents, clocks and providers for routine tests. Report skipped checks and failed live trials by name.

### Shared worker sandbox for errors and meetings

Build this profile for 2.5 and reuse it in 2.11. Give each worker only the scratch checkout, task data and draft output folder. Use the harness OS sandbox. For Codex, select `workspace-write` and disable network access for tools. For Claude, sandbox Bash and limit network access to the model API. Deny access to agent credential directories, including `~/.claude` and `~/.codex`. Disable WebFetch, WebSearch and all MCP tools in the worker. The trusted launcher owns the agent login. If the harness cannot enforce the profile, refuse the task before it sees the transcript or error.

### How a step reaches Dictaria

Use a small, deterministic local MCP client as the intake step. It calls Dictaria over HTTP with an OAuth token stored in the OS keychain. It exposes only list and read operations, follows pages, and writes meeting JSON for 2.10. A separate extraction session has no tools. It returns only schema-validated task data. No worker receives the token or access to Dictaria.

If a site needs an agent for intake, first extend the engine to pass the server only to that intake session through ACP `session/new` and its `mcpServers` field. Require HTTP MCP support from that adapter. Never register Dictaria at user scope. Before enabling a schedule, test list and read on one test meeting with the real adapter or helper. Check stable IDs, paging, read-only access and expired OAuth. A missing login or incomplete page stops intake. Live access and scopes still need verification. [ACP session setup](https://agentclientprotocol.com/protocol/v1/session-setup)
